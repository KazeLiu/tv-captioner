# 打包说明：给其他 Windows 机器使用

目标是让普通使用者不碰命令行：

```text
双击 TVCaptionerBackend.exe -> 自动打开浏览器 -> 网页里下载模型/上传视频/生成字幕
```

## 方案 A：便携版

便携版是推荐给普通用户的交付方式。它不需要用户安装 Python，也不需要用户安装 `llama-cpp-python` / GGUF 运行库。你在开发机上构建一次，然后把整个文件夹拷到其他电脑。

在开发机 PowerShell 里运行：

```powershell
cd D:\code\tv-captioner\services-backend
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\build-portable.ps1
```

生成目录：

```text
D:\code\tv-captioner\services-backend\dist\TVCaptionerBackend
```

把这个 `TVCaptionerBackend` 文件夹整个复制到目标机器，双击：

```text
TVCaptionerBackend.exe
```

打包脚本会把 `llama_cpp` 和它依赖的 DLL 一起放进便携目录。构建结束时还会检查：

```text
dist\TVCaptionerBackend\_internal\llama_cpp\lib\llama.dll
```

如果这里缺文件，脚本会直接失败，避免发给用户后才发现翻译不能跑。

## 方案 B：安装包

先按“方案 A”生成便携版。

然后安装 Inno Setup：

```text
https://jrsoftware.org/isinfo.php
```

用 Inno Setup 打开：

```text
D:\code\tv-captioner\services-backend\packaging\TVCaptionerBackend.iss
```

点 Compile，就会生成一个安装程序：

```text
TVCaptionerBackendSetup.exe
```

目标机器双击安装，桌面会有快捷方式。

## 模型怎么处理

有两种打法。

### 小安装包

安装包只带后端程序，不带大模型。

优点：

- 安装包小。
- 方便更新程序。

缺点：

- 目标机器第一次使用时，需要在网页里点下载模型。

### 完全离线安装包

你先在开发机网页里把模型下载好，然后打包前把模型放进便携目录：

```text
dist\TVCaptionerBackend\models\asr
```

翻译模型走 GGUF 文件，不需要 Ollama。打包前如果你想让目标机器离线可用，把翻译模型放进便携目录：

```text
dist\TVCaptionerBackend\models\translate
```

优点：

- 目标机器可以不联网。

缺点：

- 安装包会非常大，可能 8GB 到 20GB。

## 关于翻译运行库

当前版本已经去掉 Ollama，翻译测试使用 `llama-cpp-python` 直接加载 GGUF。真正发给别人用时，不建议让用户自己安装 GGUF 运行库；这个库应该由便携版或安装包内置。

推荐分成两层：

1. 运行库：随 `TVCaptionerBackend.exe` 一起打包，用户无感。
2. 模型文件：按需下载或随离线包内置，用户只需要在网页里看状态、按目录放模型。

如果你只是自己开发调试，才使用源码目录里的 `首次安装并启动.bat`，它会创建虚拟环境并安装 `requirements.txt`。

我建议路线是：

```text
开发机：源码目录验证 faster-whisper + GGUF 翻译
给用户：便携版或安装包，内置 GGUF 运行库
离线场景：安装包再按需内置 ASR 模型 + GGUF 翻译模型
```
